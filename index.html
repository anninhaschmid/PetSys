Etapa 1 • Contextualização da Organização

PetShop & Clínica Veterinária Amigo Fiel

Projeto de Arquitetura Computacional e Engenharia de Segurança de Informação (A3 - 2026)

Desafio Problema Motivador

A gestão anterior baseada em fichas físicas de papel e planilhas descentralizadas resultava em perdas frequentes de históricos vacinais, risco de adulteração de prescrições e vulnerabilidade total na exposição de dados pessoais (PII) de tutores.

Meta Objetivo do PetSys

Implantar uma aplicação centralizada para gestão médica e operacional, assegurada por autenticação PBKDF2 com Salt, controle RBAC rigoroso, segmentação de rede por VLANs e trilhas de auditoria imutáveis.

Diretrizes LGPD & Conformidade

Garantia de privacidade e conformidade com a LGPD para tratamento de dados cadastrais dos tutores, e isolamento estrito dos prontuários clínicos sob a guarda do corpo veterinário.

Perfis de Usuário & Mapeamento de Funções (RBAC)

Atendente (Recepção)

Efetua cadastro de tutores/pets, agenda consultas e emite vendas. Acesso negado aos prontuários clínicos.

Médica Veterinária

Acesso exclusivo para consulta e registro de anamneses, cirurgias, prescrições e vacinação no Prontuário Eletrônico (PEP).

Administrador de TI

Gerencia contas, infraestrutura de rede e rotinas de backup. Sem acesso ao PEP (Separação de Deveres).

Classificação da Informação & Categorias de Dados

Dados Pessoais (PII) Tutores

Nome completo, CPF, telefone celular, endereço residencial e histórico financeiro de compras.

Dados Clínicos dos Animais Dados Sensíveis

Anamneses veterinárias, dosagens de medicamentos, laudos cirúrgicos e vacinas aplicadas.

Credenciais & Logs Segurança

Hashes criptográficos PBKDF2, salts de 16 bytes, assinaturas HMAC-SHA256 e logs Syslog RFC 5424.

Etapa 3 • Fundamentos Ciber-Hospitalares

Mapeamento dos 5 Princípios da Segurança (CIAAN)

Princípio (CIAAN) Questão Central Mecanismo Técnico Implementado no PetSys
Confidencialidade Como garantir que apenas autorizados acessem os dados? Controle RBAC estrito com restrição ao PEP para Atendentes e Admin, mais encriptação transparente AES-256 no banco de dados.
Integridade Como garantir que as informações não sejam alteradas? Assinatura criptográfica HMAC-SHA256 validando cada prontuário e Prepared Statements contra SQL Injection.
Disponibilidade Como manter os serviços ativos sem interrupções? Nobreak UPS 1200VA com autonomia para desligamento seguro, RAID 1 de espelhamento e política de backup 3-2-1.
Autenticidade Como validar a real identidade dos usuários? Hash PBKDF2 com 100.000 iterações, Salt individual de 16 bytes e bloqueio de conta (*Account Lockout*) após 5 falhas.
Não-repúdio Como comprovar irrefutavelmente a autoria das ações? Trilhas contínuas de audit log em formato Syslog RFC 5424 com carimbo de data/hora UTC e ID do usuário.
Etapa 4 • Gestão de Riscos & Vulnerabilidades

Mapeamento de Ativos Críticos e Vetores de Ameaça

Principal Vetores de Ameaça
  • Phishing por E-mail: Tentativas de roubo de senhas dos funcionários da recepção via links maliciosos.
  • Ransomware: Encriptação indevida do banco de dados por execução de anexos infetados.
  • SQL Injection (SQLi): Manipulação de parâmetros de busca no sistema web para extração não autorizada.
  • Ataques de Força Bruta: Tentativas automatizadas de adivinhação de senhas de usuários.
Ativos Críticos do PetSys
  • Base de dados de Prontuários Eletrônicos (PEP) dos animais atendidos.
  • Dados de identificação e contato (PII) dos tutores de animais.
  • Chaves criptográficas HMAC e hashes de senhas dos usuários.
  • Disponibilidade do sistema para recepção e atendimento médico de emergência.

Etapa 6 • Autoavaliação de Segurança

Análise Crítica & Fragilidades Identificadas

Revisão arquitetural identificando 3 limitações no projeto e suas respectivas contramedidas recomendadas.

Fragilidade 1 ISO 27001 (A.9.4.2)

Ausência de Rate Limiting por IP no Proxy Web (Nginx)

Diagnóstico: A aplicação limita falhas por usuário, mas não restringe requisições em massa originadas do mesmo endereço IP.
Mitigação: Ativar a diretiva limit_req_zone no servidor Nginx para limitar requisições de login a no máximo 5 por minuto por IP.

Fragilidade 2 NIST SP 800-92

Armazenamento de Audit Logs no Disco Local do Servidor

Diagnóstico: Caso um atacante obtenha privilégios de administrador no servidor local, os logs em disco podem ser adulterados.
Mitigação: Configurar encaminhamento remoto contínuo de logs via protocolo RSYSLOG encriptado com TLS para um servidor SIEM isolado.

Fragilidade 3 NIST SP 800-57

Chave Criptográfica HMAC Estática sem Plano de Rotação

Diagnóstico: A chave secreta utilizada para assinar os prontuários permanece a mesma indefinidamente.
Mitigação: Integrar a aplicação a um serviço de gerenciamento de chaves (KMS) com ciclo automatizado de rotação anual de chaves.

Relatório Acadêmico Final — Projeto A3 Sistemas Computacionais e Segurança

Organização Estudada: PetShop & Clínica Veterinária Amigo Fiel

Resumo Executivo: O presente trabalho apresenta o projeto completo de engenharia de segurança de informação para a clínica veterinária Amigo Fiel. A infraestrutura digitalizada foi concebida para proteger o Prontuário Eletrônico (PEP) dos animais e os dados pessoais (PII) dos tutores em estrita conformidade com a LGPD e normas internacionais ISO 27001 e NIST SP 800.

Síntese dos Resultados Técnicos:

  • Autenticação robusta utilizando algoritmos PBKDF2 com 100.000 iterações e Salts individuais de 16 bytes.
  • Implementação da política de Account Lockout ativada após 5 falhas consecutivas de login.
  • Segregação de privilégios RBAC aplicando o Princípio do Menor Privilégio e Separação de Deveres entre atendimento, saúde animal e suporte de TI.
  • Verificação de integridade em tempo real via HMAC-SHA256 para prevenir modificações não autorizadas em históricos médicos.
  • Rede corporativa dividida em 4 VLANs com borda protegida por Firewall NGFW e WAF ModSecurity.

import sqlite3
import hashlib
import hmac
import time
from datetime import datetime, timezone

ARQUIVO_DB = "petsys_producao.db"
ARQUIVO_LOG = "petsys_auditoria.log"
CHAVE_HMAC_MESTRE = b"ChaveSecretaHMACPetSys2026AmigoFiel"

def gravar_log_auditoria(username, acao, status, detalhes=""):
    agora = datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M:%S UTC")
    linha_log = f"[{agora}] UTILIZADOR='{username}' | AÇÃO='{acao}' | STATUS='{status}' | {detalhes}\n"
    with open(ARQUIVO_LOG, "a", encoding="utf-8") as f:
        f.write(linha_log)

def inicializar_banco_dados():
    conn = sqlite3.connect(ARQUIVO_DB)
    cursor = conn.cursor()
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS usuarios (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            username TEXT UNIQUE NOT NULL,
            nome TEXT NOT NULL,
            perfil TEXT NOT NULL,
            salt TEXT NOT NULL,
            senha_hash TEXT NOT NULL,
            tentativas_erradas INTEGER DEFAULT 0,
            bloqueado_ate REAL DEFAULT 0
        )
    ''')
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS prontuarios (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            pet_nome TEXT NOT NULL,
            especie TEXT NOT NULL,
            tutor TEXT NOT NULL,
            historico_clinico TEXT NOT NULL,
            hmac_checksum TEXT NOT NULL
        )
    ''')
    conn.commit()
    conn.close()

if __name__ == "__main__":
    inicializar_banco_dados()
    print("PetSys Security Engine Python Backend Inicializado.")
